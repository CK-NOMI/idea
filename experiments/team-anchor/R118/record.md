# team-anchor/R118｜预训练模型上的锚点创新量与稀疏验证因果审计

日期 2026-11-25（Asia/Shanghai）。研究开始读取 GitHub `main` 的 `8c1347f533c5dcbde5f3ef387493b84c12969cf6`，README blob `20f01001d690d1c583f1fa640e7e81a865a40517`（4207 行、1,078,712 字节）。取得完整 README，筛查近邻、失败库、G1–G7，复核 R44、R104、R110、R115、R116、R117 的相关记录、公开结果和适用代码，以及 R117 后的三个 GPU 准备提交，未独立复跑全部团队。历史分数指各自评分口径。

## 问题与信息边界

R116 的事后窗口选择只覆盖实跑的策略集合。它削弱了把窗口自调当主贡献的理由。R110 的 1.405× 是真实小模型 CPU 时延峰值，但正式质量未匹配。R117 的 0.31% NLL 差来自两个同尺度 7,264 参数模型，且离线抽取了完整稠密特征。本轮检验两个直接决定能否放大这项结果的问题。

1. 用预训练 Transformer 的当前浅层特征拆出可预测深层成分以后，锚点还能提供多少有效残差信息？这决定新正式模型在相同刷新率下能否接近教师。
2. 当只计算锚点深层输出时，哪些 K/V 仍需计算？这决定观察到的锚点数量能否对应可消除的实际计算。

协议设想中，文档、逐 token 特征和拒绝轨迹停留在客户端。客户端按当前冻结检查点和固定浅层切分得到 xₜ 与校准用稠密状态 dₜ。对角拟合每客户端只需上传计数及 Σx、Σr、Σx²、Σxr，r=d−x。区域聚合同一坐标的统计量，云端汇总；区域对角桥向全局系数 50% 收缩。滞后系数另需汇报每个偏移和候选系数的校准损失。每客户端 4H 个浮点和一个计数，H=2048 时仅对角拟合的 float32 统计为 32 KiB 加计数，每种切分单独算。实际网络通信与隐私泄露量未测；聚合统计本身不提供差分隐私。同信息、同预算、同区域委托的平坦系统可计算相同结果。

## 机制与可验证性质（T/H）

令 g(x)=b+m⊙x，a 为最近的已确定锚点，j=t−a。锚点使用 dₐ，其他位置使用

`h_t = x_t + g(x_t) + gamma_j [r_a - g(x_a)]`。

草稿可用 `x_t+g(x_t)` 起草，正式目标在相同浅层状态上做上述晚融合。分布由模型原 RMSNorm 与 LM head 读出。训练先用共享检查点上的对角岭回归拟合 g，再在不同文档上标定各偏移的 γ。强对照保持切分和锚点完全相同，包括 R117 式直接搬运 `x_t+gamma_j r_a`、只在锚点计算深层状态、每 token 使用同一对角桥、全局桥和无校正浅层。这里的正式目标会改变，稠密模型仅用于质量与算子级因果核对。

**命题 1（条件收益）。** 记 `u_t=r_t-g(x_t)`，`u_a=r_a-g(x_a)`。给定滞后 j 和已定义的样本分布，若 E‖uₐ‖²>0，在隐藏态平方误差下，最优无约束 γ 为 E⟨uₜ,uₐ⟩/E‖uₐ‖²。取约束 [0,1] 时夹到该区间。展开目标得 `E‖u_t‖² - 2 gamma E<u_t,u_a> + gamma² E‖u_a‖²`，故在 [0,1] 内存在严格改善当且仅当交叉项为正。若 uₐ 恒零，没有增益。NLL、教师 KL、实际接受率和执行时延不服从这个平方损失等式。实验按校准 NLL 选择 γ。若真实校正每 token 都变化，例如去掉自回归可预测均值后 uₜ=−uₐ，正权重锚点搬运只会增大误差。

**命题 2（最后一层锚点的精确性和跨层失效反例）。** 对固定检查点，设 xₜ 是最后一层输入。最后一层每个 token 的 K/V 来自 norm(xₜ) 与位置编码，不依赖该层的输出；锚点的注意力仅依赖其 query 和因果前缀所有 K/V。故保留所有前缀 K/V 并仅在锚点求 Q、注意力、O 和逐位置 MLP，在实数算术下给出该层相同的锚点输出。对多个连续省算层不能直接类推。取两位置的标量例子，第一层使较早非锚点的值变化 δ，下一层令锚点均匀注意两个位置且 V 为恒等，省略早位置更新会使锚点的第二层注意力输出偏差 δ/2。硬件精度和不同矩阵形状可产生舍入误差，故核对 hidden 数值和实际 argmax。该命题保留全部最后一层 K/V，可节约的工作只包括最后一层 Q/注意力/O/MLP 的部分位置。

**分布口径。** 给定严格因果的正式目标 p 与内生草稿 q，每个位置从 q 抽样，接受概率 min(1,p(X)/q(X))，拒绝后按 (p−q)₊/TV(p,q) 补样，提交 token 的条件概率质量为 min(p,q)+(p−q)₊=p。拒绝后丢弃未提交草稿，继续根据真实提交前缀构造 p，逐步条件化得序列分布。贪婪逐位置验证采用共同的 tie 规则。每个请求固定检查点、门和校准参数，目标不得随验收事件或系统到达时序变化。温度、top-p 若启用，须作用在实际正规化 p/q 上并使用真实采样概率。新机制未实现自由生成、未测试随机、EOS 和有限精度生产等价。

**成本界。** 若剖析得最后一层可跳过部分占匹配基线关键路径比例 f，跳过比例 s，新增桥、缓存和同步开销占 h，串行且其余路径不变时加速为 1/(1−fs+h)。1.5× 要求 fs−h≥1/3。B=4 时若近似跳过该阶段 3/4，且 h=0，须 f≥4/9。在多层删减时，必须另外证明保留因果前缀 K/V 的生成方式。单卡的小实验不评估 R117 假设的双资源重叠，也不以层数或查询数量推得 GPU 速度。

## 初筛设置与实际 CPU 验证（E）

[AG News 的发布者仓库](https://github.com/mhjabreel/CharCnn_Keras/tree/555590db4219b1243abb1918effd6a7425a2d75f/data/ag_news_csv) 的公开固定 train/test CSV。按原数据顺序和四类别各取六篇可用文档，共 16 训练、8 校准、24 测试。类别作为逻辑客户端且两个类别组成一区。不同尺度使用同一文档子集。前 48 个 token，预测标签右移，无生成。四线程 Apple ARM CPU、PyTorch 2.5.1、Transformers 4.48.3、FP32。每个模型三切分、三个间隔，配对文档 bootstrap 3,000 次、种子 118，未做多重比较修正。两个源权重与输入文件的校验和在对应输出中。[135M 模型](https://huggingface.co/HuggingFaceTB/SmolLM2-135M) · [360M 模型](https://huggingface.co/HuggingFaceTB/SmolLM2-360M)

| 检查点与切分 | B | 稠密 NLL | 直接搬运 | 校正后搬运 | 区域校正 |
|---|---:|---:|---:|---:|---:|
| 135M，3/30 | 4 | 4.0053 | 11.3635 | 8.4060 | 8.3837 |
| 135M，29/30 | 2 | 4.0053 | 4.9353 | 5.2883 | 5.2784 |

在 B=4、最浅切分，校正后搬运相对直接搬运使 NLL 分别降低约 26.0%、6.7%，但仍比稠密模型高约 109.9%、125.2%。最后一层切分的 B=2，直接搬运仍比稠密 NLL 高约 23.2%、12.8%；改用对角校正反而变差。360M 最后一层三个 B 的直接搬运均退化成校准选择 γ=0 的周期深算。因此 R117 的小 NLL 差不能推及这两套冻结模型和当前配方，结论也不排除改变架构或训练后可以复用。区域校正与全局校正的差异较小、跨尺度不稳定；多个探索性区间跨零。四客户端两个区域均在同一进程内聚合统计，未测真实 HFL。

同一原始模型的单层稀疏 Q/注意力原型另执行每模型 12 篇文档、最多 64 tokens。两个模型各 623 个被审计锚点，两套单层原型全部保留 argmax，最大隐藏绝对偏差各 2.442×10⁻⁴。用上上层状态替换非锚点 K/V 来源后，135M 只保留 605/623、360M 只保留 610/623 个 anchor argmax，给出多层近似省算会污染锚点的真实反例。全前缀 K/V 仍参与注意力。此原型未测试候选端到端稀疏速度。

## 验收条件与下一道实验门槛

本轮只筛查质量和既有基线。后续的好结果预定义为同时达到以下条件。

- 新正式模型相对于原稠密教师的测试 NLL 相对增幅 ≤1%，其文档 bootstrap 95% 单侧上界 ≤1%。另针对长尾与上下文任务预先设任务非劣效界，按独立请求和种子报告，不能用总体均值代替。
- 在同质量下对比调优 LayerSkip、普通稀疏 AR/SD、质量匹配的多尺度模型和允许同区域委托的平坦联邦。完成预定固定工作量，生命周期总耗时（训练、推理、通信、验证、缓存、回退和额外学习）减少 ≥15%，或固定总成本的有效工作量提升 ≥20%，且 CI 达到相应门槛。相对于最强 SD 基线的 1.5× 保留为独立的推理竞争力目标。
- 在同样字节、算力与数据驻留能力下，分别移除 SD 驱动的正式模型训练反馈、区域适配，检验两条因果方向；支持同地域委托的强平坦联邦与普通 HFL+SD 均须进入评估。等信息平坦模拟等价意味着仅改拓扑命名无法过 G2。
- 两种预训练规模、至少三种非 IID / 网络延迟设定和三个独立训练种子，公开真实任务，1–2 张 40 GB 或等限制硬件。当前两个 SmolLM2 规模共享文档，不是两组独立训练实验。

若可保留唯一方向，下一轮只实现一个因果稀疏后缀，与高质量冻结稠密教师配对。每层 K/V 构造显式读取始终可用的浅层序列以及已提交锚点历史，并在该新架构内训练，不把旧稠密的多层 K/V 当作可免费得到。异质度先只保留三个实际领域，训练全局版与区域版共享同一个低秩参数预算。以预先登记的 NLL 界和实测关键路径 `fs−h` 双门槛决定是否增加 GPU。第一门失败即关闭这一候选，不追加区域门控训练。第一门通过后才有必要开展质量约束下的同目标自由生成 SD，记录拒绝回退、HBM/KV 流量和真实网络传输。其负反馈训练设想，仍需用冻结对照检验拒绝轨迹是否提供超过普通难例采样的增量。

具体起始原型（H）：一次把每个浅层 xₜ 编码进共享因果记忆 Mₜ。锚点 a 的后缀层 i 仅更新 zᵢ,ₐ，用 zᵢ₋₁,ₐ 作 query，读 M≤ₐ 和先前锚点的压缩状态。用同一 GPU 上的等预算稠密后缀、每层重新投影的多尺度后缀和共享 M 版本分离节省来源。先在一张 3090 上用 1B 冻结主干并拟合小后缀，分离质量初筛与速度测量。生命周期口径取 `T_total=T_adapt+T_upload+T_aggregate+T_inference+T_verify+T_rollback`，两个运行若每请求节省 s>0 但适配多花 Δ 秒，则仅 N>Δ/s 才有总耗时优势。设备并行时应从相同计时边界测联合墙钟时间，避免重复加总已重叠阶段。这个原型、通信和生命周期比较均未执行。

研究内容原创性综合 **7.4/10（未通过）**。分项各为 0–2 分：计算对象 1.5，机制与最近论文差异 1.4，HFL–SD 双向不可替代性 1.0，可证伪性 1.9，算法代价或质量增益 1.6。对角回归和因果稀疏查询已有通用解释，冻结桥的质量缺口和同信息平坦等价限制后两者的论文主张。七门同时通过和好结果把握 80% 均缺证据，未给出数值成功概率。历史其他候选分数保留。

### 1B 的 GPU 生成和锚点质量（E）

**Transformers 4.48.3。** 单卡 FP16，batch 1、输入截断 64、每请求最多 32 个新 token。8 校准 / 8 留出请求、每文档全部 7 个模式，随机执行顺序，合计 112 次有效配对。生成耗时含 prefill 与 decode，排除模型加载、切词、网络和训练。选型依据校准集一致性与吞吐，未经测试集重选。校准选出 exit 3/K2，留出与 AR 分别为 31.05、35.92 token/s，速比 0.864×（配对文档 bootstrap 95% 区间 0.798–0.966）。256 token 总数相同，留出 AR 7.126 s，SD 8.245 s。SD 有 1/8 条请求生成序列不一致，属于有限精度与实现排查的证据，未单独确定原因。四个留出请求的另外一组 CUDA event 剖析中，所选 SD 的浅层 draft forwards 161 次、1.097 s；完整 verifier forwards 84 次、2.467 s，包含前向投影和缓存，阶段 event 时间不外推为可移除 wall time。

仅 15/16、B=2 在该任务达到预定 NLL 初筛（按文档配对、重采样中重新计算分母的 10,000 次 bootstrap，95% 单侧上界 +0.947%；B=4 的单侧上界 +1.417%）。该筛查涉及多个配置，未做多重比较校正，还需独立任务复验与长尾非劣效核对。全局桥相对保持同锚点预算的周期深算在 1B 九个配置均变差，区域对全局桥的配对区间都跨零。相比 R117，没有观察到区域适配或历史深层残差搬运增益。FP32 单层稀疏原型另核对 620 个锚点，全部匹配稠密 argmax，最大隐藏绝对误差 7.63×10⁻⁵。替换上一层的非锚点状态后只匹配 619/620。

**官方 LayerSkip 复用实现。** 原始 LayerSkip checkout 固定在 `494752e5fbb0a82989f6cb384841684b1c2ef5c3`，复用知识库 R104 runner。首次启动先遇到复制 checkout 的归属校验，修正归属后上游 requirements 指定的 Transformers 4.50.0 仍在 split forward 因缺 `position_embeddings` 失败。用保留旧 Llama decoder 接口的 Transformers 4.46.3、Tokenizers 0.20.3 后原样运行上游复用算法。单卡 FP16，8 校准 / 8 留出，9 个 SD 设计加 AR，合计 160 条有效配对，最多 32 个输出 tokens。与 HF 集成版分别比较各自 AR，官方 runner 计入切词和解码后的文本解读，未对输入做 64 token 截断。校准锁定 exit 4/K2。留出 AR 7.794 s、SD 7.786 s，均生成 256 个 tokens，全部 8/8 逐 token 一致，吞吐速比 1.001×，配对文档 bootstrap 95% 区间 0.917–1.105，未观察到稳定胜过 AR。SD 留出请求的接受率宏平均 34.09%。R104 固定区域选型相对全局选型的总时间增加约 0.11%。候选 exit 3/K2 的校准序列有 1/8 不一致，按事前规则排除。与上文的 0.864× 分属不同实现和计时边界，不混合。

**最后一层实际剖析与理想反事实（E/P）。** 8 个留出请求，256 个输出 token。预热后，未插桩总耗时 6.897 s，插桩总耗时 6.888 s；两次输出逐 token 一致。最终层全算子 CUDA-stream event 合计 0.406 s（占插桩 wall time 5.90%），其中 prefill 0.0127 s，自回归步 0.3935 s。假设串行其他成本不变，免费删除整个最后一层对应 1.063×；只免费删除一半非 prefill 的最后层调用，按两种奇偶起点折算 1.028–1.030×。实际稀疏方式还需为所有 token 维护最后层 K/V，无法删除整个最后层。这是基于真实分阶段测量的有利成本估算，未执行稀疏推理吞吐对比或流水线加速。与 1.5× 目标所需的净 33.3% 关键路径节省相距很大。该结论限当前单卡、实现与长度设置。

## G1–G7 和裁决

| 门 | 本轮状态 | 可复核依据 |
|---|---|---|
| G1 原创性 | 未通过，7.4/10 | 有可检验的残差分解和多层稀疏因果反例，但线性桥、复用及多尺度深算均有直接近邻；没有完成文字查重 |
| G2 双向必要性 | 未通过 | 1B 区域对全局无可信改善，普通平坦委托可复制统计量，没有 SD 反馈联邦学习的因果实证 |
| G3 正确性 | 部分 | 形式化证明了固定新目标的条件采样等价与单层锚点性质；有浮点核对及跨层反例；未实现新目标自由生成，Transformers 基线存在 greedy 序列差异 |
| G4 实验 | 部分，未通过 | 135M、360M、1B 三个真实检查点，公开新闻文本，实际 CPU 和 3090，每尺度单一数据/训练设定 |
| G5 端到端 | 未验证 | 实测既有自投机基线与 GPU 阶段；只通过质量初筛的最后一层 B=2 距性能目标太远，新模型与学习通信全成本未执行 |
| G6 成功把握 | 未通过 | 缺独立、匹配质量的速度与区域因果增量，持有 80% 把握无依据 |
| G7 可复现 | 本轮可审计，整体部分 | 提供版本固定、模型校验、环境、原始请求记录、算子审计、脚本和失败情况；完整 HFL 与两资源流水线还没实现 |

**裁决：Reject and Pivot（冻结锚点桥作为论文主机制），Retain（单层的因果结构、跨层反例、质量和性能边界）。** 不再扫同一冻结模型的锚点间隔、对角桥或区域正则。只有“训练让多层稀疏 K/V 可用”这一新假设通过前述预先设定的质量与关键路径筛查时，才值得重新考虑；届时需与 BLT/H-Net 的多尺度对照、调优 LayerSkip 和同能力平坦联邦比较。

## 复现

用 Python 3.11、PyTorch 2.5.1、Transformers 4.48.3。设置 `DATA_ROOT` 后可从仓库根运行 `bash experiments/team-anchor/R118/run_3090.sh`。官方参照需 `facebookresearch/LayerSkip` 的 `494752e5fbb0a82989f6cb384841684b1c2ef5c3` checkout、兼容的 Transformers 4.46.3，用本轮 `run_official.sh` 调用 [R104 官方脚本](../../team-far/R104/official_pilot.py)。最终层时序由 `profile_final.py --root "$DATA_ROOT/hfl_sd_r118" --out <output.json>` 实测。SmolLM2 则用 `prepare.py --root <directory> --model 135M` 或 `360M`，`quality.py --root <directory> --out <output.json> --per-class 6 --context 48 --exits 3 15 29 --blocks 2 4 8 --threads 4`，360M 改 exits 为 `3 16 31`。稀疏算子可用 `anchor_audit.py --root <directory> --out <output.json> --threads 4`，1B 运行加 `--device cuda`。仅用于研究筛查。原始 JSON/JSONL 文件均在本目录，URL、实验标识和模型元数据可查。
