## Research direction and falsifiable screen
Test where native MTP actually leaves exposed generation and learning headroom before proposing a new federated mechanism. For fixed nonterminal K, baseline accepted draft mean A, same per-cycle cost and no other overhead, perfect acceptance gives relative commit-rate (K+1)/(1+A). E.g. K2 A=1.5 ->1.2x, K2 A=1.0 ->1.5x, K4 A=3 ->1.25x. Not a latency bound when changing K/cost. A large gap against AR is not a gap against native MTP. At fixed generation share f, generation speed S and normalized incremental exposed overhead h, lifecycle speed = 1/(1-f+f/S+h); to reach 1.5x overall requires f(1-1/S)>=1/3+h. This is accounting, not new theorem. Proposed research hypothesis (unverified): learn which version-specific native MTP computation is reusable or must be refreshed across client/edge/cloud learning updates; compare fully refreshed native MTP, ordinary parameter-efficient updates with caching and same-resource delegated flat. R01/R03/HC-R04/R45/R77/R86 already investigated related version/cache ideas; no new mechanism claimed, no parameter freeze assumed to preserve quality. Need real gradient/parameter dependency, real resource cost and exact same target, not synthetic routing.
